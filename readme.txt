Автоматична відправка замовлень WooCommerce у OneBox OS: створення процесу-замовлення в CRM після checkout, повторні спроби, журнал подій.

== Опис ==

Плагін зв'язує WooCommerce з OneBox OS через REST API v2 (POST /api/v2/order/set/ на домені вашого OneBox). Кожне нове замовлення магазину автоматично створюється в OneBox як процес-замовлення з клієнтом, товарами та коментарем; товари каталогу знаходяться або створюються за артикулом (SKU).

= Можливості =

* Відправка замовлення одразу після checkout (класичний чекаут і Checkout Blocks) або при переході в один із вибраних статусів
* Дедуплікація подвійна: externalid `wc-{id}` (upsert на боці OneBox) + збережений OneBox ID у меті замовлення — жодних дублів
* Клієнт передається полями clientname/clientemail/clientphone/clientaddress, товари — масивом products із прив'язкою до каталогу (productinfo: назва, артикул, externalid)
* Необов'язкова маршрутизація: ID бізнес-процесу (workflowid), етапу (statusid) та джерела (sourceid)
* Позначка оплати: для сплачених онлайн замовлень у коментар процесу додається «✅ Оплачено онлайн» (опційно)
* Повторні спроби при збої: 3 спроби з паузами 5 хв / 30 хв / 2 год (WP-Cron)
* Метабокс на сторінці замовлення: статус синхронізації, OneBox ID, кнопка «Відправити повторно» (для вже відправлених — оновлення того ж процесу)
* Кнопка «Перевірити з'єднання» на сторінці налаштувань (токен + список бізнес-процесів)
* Журнал останніх подій синхронізації (вкладка «Журнал»)
* Шифрування API-пароля у БД (libsodium з HMAC-фолбеком), токен кешується і оновлюється автоматично
* Нормалізація телефону покупця до E.164 (+380...)
* HPOS-сумісність (custom order tables), робота лише через WC_Order CRUD
* Фільтр `cc_onebox_order_payload` і хук `cc_onebox_order_sent` для сторонніх інтеграцій

= Вимоги =

* WooCommerce 7.0 або новіше
* PHP 7.4+
* OneBox OS з застосунком «Користувачі та співробітники» та REST API паролем співробітника

= Як це працює =

1. Клієнт оформлює замовлення у магазині
2. Плагін отримує токен (POST /api/v2/token/get/ з API-логіном і паролем) і надсилає замовлення POST /api/v2/order/set/ на домен вашого OneBox
3. OneBox повертає `{"status":1,"dataArray":[id]}` — ID процесу зберігається у меті `_cc_onebox_order_id`
4. Якщо OneBox недоступний — спроба повторюється автоматично (до 3 разів)
5. Менеджер бачить статус і ID у метабоксі замовлення та в журналі

== Встановлення ==

1. Залити папку плагіна у `/wp-content/plugins/onebox-sync-for-woocommerce/`
2. Активувати у меню «Плагіни»
3. WooCommerce → OneBox Sync → ввести домен OneBox, API-логін і API-пароль
4. Натиснути «Перевірити з'єднання», зберегти налаштування

== Часті питання ==

= Звідки взяти API-логін і пароль? =

Кабінет OneBox OS → застосунок «Користувачі та співробітники» → картка співробітника → REST API пароль. Логін — логін цього співробітника. Плагін сам обмінює їх на токен через /api/v2/token/get/; пароль зберігається у БД в зашифрованому вигляді.

= Чи створюються дублі при повторній зміні статусу? =

Ні. Плагін передає externalid `wc-{id}` (OneBox сам оновлює знайдений процес) і додатково зберігає OneBox ID у меті замовлення.

= Що робить кнопка «Відправити повторно»? =

Якщо замовлення ще не в OneBox — створює процес. Якщо вже відправлене — оновлює той самий процес актуальними даними (товари оновлюються, а не дублюються).
